## P1 — POC / 技术验证 ✅

**目标**：在写任何真正的功能之前，先证明三件事——技术栈能在三个平台跑通、构建产物体积可接受、关键风险（Lua 沙箱）有可用的原语。

**交付物**

| 项 | 内容 |
|---|---|
| 工程骨架 | CMake + Qt6 + submodule 依赖，三 target（core / bs / batchsmith） |
| 构建链路 | CMakePresets（本机 + CI 各一套），Debug/Release 均可构建 |
| 测试链路 | doctest + ctest，core 不依赖 QtWidgets 因此可在无图形环境跑 |
| CI | 三平台矩阵：构建 + 测试 + 打包 + artifact；打 `v*` tag 自动发 Release |
| 打包脚本 | `packaging/package-{windows,macos,linux}.sh` |
| 首个真实功能 | 自然排序比较器 `natural_compare` |
| 文档 | 本文件、技术方案、Phase 1 施工记录、README |

**验收（已实测通过）**

- Debug 构建 0 警告 0 错误；Release 在 `-Werror` 严格模式下同样通过
- `ctest`：10 用例 / 246 断言全通过
- `clang-format --dry-run --Werror` 合规
- CLI `bs --version` 正常，中文输出无乱码
- GUI 启动存活，AUTOMOC 元对象链路可用
- Windows 打包端到端跑通：**11.45 MB zip**

**刻意不做**：任何 DSL、任何文件操作、任何真实数据模型。P1 只验证"链路"，不验证"功能"。

**收获的关键结论**（影响后续所有阶段）

1. 产物体积实测 **11.45 MB**，比方案估算的 15–25 MB 更好 → 「轻量化」这条约束已满足。
2. 沙箱能力在 C++/PUC Lua 上与 Rust/mlua **完全等价**，不构成选型差异。
3. **不用 LuaJIT** —— JIT 轨迹不触发 `LUA_MASKCOUNT` 钩子，死循环拦不住。
4. 依赖用 submodule 而非提交进仓库，本仓库自身体积保持在 ~300 KB。

## P2 — 表达式内核 ✅（0.3.0 完成）

**目标**：DSL 能被正确编译，并在沙箱中安全执行。**这是整个项目技术风险最高的一步，也是唯一"做不对就全盘皆输"的一步。**

**交付物**

| 模块 | 内容 |
|---|---|
| 扫描器 | `$...$` 分段、`\$` 转义、区段内首个未转义 `$` 结束、未配对 `$` **编译报错** |
| 编译器 | DSL → Lua 源码；**编译一次产出 `return function(i) … end`**，逐行调用而非逐行编译 |
| 单行转义器 | 不用 `string.format("%q")`；自定义转义保证"一行 DSL ↔ 一行 Lua"的行号映射 |
| 沙箱 | `_ENV` 白名单 + 指令数钩子 + 内存上限 + 墙钟超时（四项齐备） |
| 逃逸面处理 | `string.rep` 等先分配后检查的函数做参数预检；不暴露 `coroutine`；限制违规在宿主侧打独立 flag，`pcall` 吞不掉 |
| 求值模型 | 行循环、`i` / `rows` 注入、补位（`__index` 惰性返回 `""`，不设 `__len`）、**行展开规则** |
| helper | 列表 / 组合 / 生成 / 文本 / 路径 / 类型 六类，见技术方案 §3.5 |
| `bs eval` | 纯函数入口：只跑编译与求值，**不接触文件系统** |

**验收标准**

1. 构想书「使用示例」一节的 **6 个示例逐字对上**给出的输出。
2. 对抗性测试全部被拦：
   - `while true do end` 在指令上限内被中止
   - `string.rep("x", 1e9)` 被参数预检拦下
   - `pcall` 无法吞掉中止（宿主仍终止整批）
   - 访问 `io` / `os` / `package` / `require` / `debug` 一律报 nil
3. `#list1` 返回**原始长度**（不含补位），越界 `list1[i]` 返回 `""`。
4. `rows` 在有无 `Ignore` 时分别取 max / min。
5. `mv $matrix(list1,list2,'-')$ out` 产出 9 行。
6. 恶意预设无法通过任何路径触达文件系统。

### ✅ 已完成（含原先记下的「必须收掉的临时实现」）

0.2.0 为了让界面能演示「输入 → 输出」加过临时求值器 `batchsmith::core::dsl::evaluate_simple`；
**0.3.0 已按计划删除**，界面改调正式的 `evaluate_template`，其单测演化为引擎测试。

| 交付物 | 状态 |
|---|---|
| 扫描器 / 编译器 / 单行转义器 | ✅ `dsl/template_scanner`、`dsl/compiler` |
| 沙箱四重限制 + 三个逃逸面 | ✅ `sandbox/sandbox`（宿主侧违规标记 + 三处参数预检） |
| 求值模型（i/rows、补位、行展开） | ✅ `dsl/engine`，含「不用行上下文只求值一次」 |
| helper 六类 | ✅ `helper/helpers`（28 个函数） |
| `bs eval` | ✅ 纯函数入口，不接触文件系统 |

**验收核对**：构想书 6 个示例逐字对上 ✅；`while true do end` / `string.rep(x,1e9)` /
`pcall` 吞错 / `io`·`os`·`require`·`load`·`debug`·`coroutine` 各有一组对抗性测试 ✅；
`#list` 返回原始长度 ✅；`Ignore` 取最短、其余取最长 ✅；`mv $matrix(...)$ out` 9 行 ✅。

**依赖**：P1。**风险**：沙箱逃逸；DSL 语义歧义（P1 已踩过一次 `natural_compare` 的方向歧义，教训是**规格注释必须把边界写死**）。

## P3 — 列表源与预设 🚧

> **进度**：列表来源（手输 / 绑定文件夹）、过滤与排序、**预设的保存 / 加载 / 管理**、
> 路径槽位与伴生绑定文件、"双击即用"的快捷方式都已落地（core + CLI + 界面）；
> `bs plan` 仍是 ⬜。

**目标**：预设能描述一组列表，列表能从真实来源取到数据。

**交付物**

| 模块 | 内容 |
|---|---|
| 预设 schema ✅ | TOML（`toml++`）；`preset` / `lists` / `output` 三段 + `version` / `level`；`[exec]` 留给 P4/P5 |
| 路径槽位 ✅ | `${input}` 形式的运行时槽位；实际绑定存在 `<预设名>.local.toml`（**预设里不存绝对路径**） |
| 列表来源 🚧 | `input`（手输）✅、`dir`（绑定文件夹）✅、`expr`（表达式生成）⬜、`snapshot`（一次性读取）⬜、生成器（`seq` / `rand` / `regex` 捕获）⬜ |
| 过滤与排序 ✅ | glob 过滤、递归开关、**自然排序**（接入 P1 的 `natural_compare`） |
| 缺省方式 🚧 | `empty` / `ignore` / `repeat` 三态：core、CLI（`--ignore`）与预设文件都支持，界面尚未暴露 |
| 预设的界面 ✅ | 「文件」：新建 / 打开 / 保存（**不问路径**，默认落进预设目录）/ 另存为；「预设」：最近用过的直接列出可一键切换 / 管理预设（重命名 / 删除 / **创建快捷方式**）/ 打开预设文件夹；启动时可带预设（`batchsmith x.toml` 或 `--preset`） |
| `bs plan` ⬜ | 生成 Plan 并打印 diff；**默认 dry-run，零副作用** |

**验收标准**

1. `bs plan <预设> --bind input=<目录>` 能正确列出目录内容并排序（`file2` 在 `file10` 前）。
2. 预览输出与实际执行结果一致——为此 `rand` 必须有可固定的种子（`seed()`）。
3. 全程不产生任何文件系统写入（用只读目录或事后校验 mtime 证明）。
4. 预设文件本身可进版本控制：不含绝对路径、无本机信息。

> 第 1 条的"列出目录内容并排序"已可用 `bs eval --list 'list1=@dir:<目录>'` 验证；
> 第 4 条已由"保存时路径自动槽位化"满足（测试里有一条断言直接扫预设文件里不含本机绝对路径）。
> 第 2、3 条随 `bs plan` 一起做。
>
> `bs plan` 需要先把预设读进 CLI —— `core::preset` 已经能读能写，
> CLI 侧只差一个子命令与 Plan 的打印格式。

**依赖**：P2。

## P4 — 计划与执行：重命名闭环 ⬜ ★

**目标**：把"安全的批量重命名"这件事真正做对。**这是判断整个项目是否值得继续的阶段。**

**交付物**

| 模块 | 内容 |
|---|---|
| Plan 结构 | 可序列化、可 diff、可单测的纯数据结构 |
| 路径绑定 | 求值那一刻快照 `(行号 → 绝对路径)`；apply 前校验路径仍存在且 mtime/size 未变 |
| 冲突检测 | 源不存在 / 两条输出同名 / 目标已存在 / 路径穿越（逃出绑定根） |
| 两阶段重命名 | 批内互换（a→b 且 b→c）与**仅大小写不同**（Windows/macOS）走临时名 |
| 执行器 | `rename` 模式：不经 shell、不启进程 |
| 撤销 | JSONL 日志 + `bs undo <日志>` 逆序回放，回放时同样做冲突检测 |
| 命令 | `bs run <预设> --apply`（不加 `--apply` 一律 dry-run） |

**验收标准**

1. 四类场景全部正确：a↔b 互换、仅大小写改名、中文路径、目标已存在。
2. `bs undo` 能**完整还原**，包括互换场景。
3. 源文件在 plan 与 run 之间被改动时，该行被拒绝执行并明确报错。
4. plan 输出的 diff 与实际执行结果 **100% 一致**。

**★ 判断门槛（沿用构想书评估的原话）**

> 这一版做完后**一周内是否真的每天在用**；若不是，就停在这一版，不要再扩列表源、生成器与并发。

**P4 不过 → 项目终止在 P4**，不启动 P5 之后。这不是保守，是避免把时间投进一个自己都不用的工具。

## P5 — 命令执行与并发 ⬜

**目标**：从"改名字"扩展到"跑命令"。

**交付物**

- `argv` 执行器：模板分词为 argv 数组，经 `QProcess::start(prog, args)`——**天生不经 shell**
- argv JSON 清单输出（**不生成 `.ps1` / `.bat`**，中文路径在那些格式下会编码损坏）
- 并发 apply（`QThreadPool` / Qt Concurrent，`jobs` 可配）；重命名因涉及临时名交换而串行
- 执行日志面板所需的数据结构（stdout / stderr / 退出码 / 耗时）
- `stdout` 模式：文本 / 剪贴板 / 写文件

**验收标准**

1. 含空格、中文、引号、通配符的参数正确传递。
2. **文件名叫 `; rm -rf ~` 也安全**——这是"不经 shell"的可验证证据。
3. 并发下输出顺序与日志一致，无交叉污染。
4. 危险操作（如 `rm`）在 dry-run 下不执行。

**依赖**：P4。

## 跨阶段约定

这些是每个阶段都必须遵守的，不是某一步的待办：

1. **安全模型不可绕过**：默认 dry-run、argv 不经 shell、执行前冲突检测、撤销日志。任何新功能接入前先问"它是否破坏了这四条"。
2. **core 只依赖 QtCore**，不引用 QtGui/QtWidgets（保证 headless 可测）。
3. **逻辑只写一次**：CLI 与 GUI 共用 core，`P6` 的验收就是这条的守门人。
4. **每个阶段的交付都要有可执行的验收命令**，不接受"看起来没问题"。
5. **冒烟判据必须是可观察的行为，不能只是"进程存活"。**
   Phase 1 就因此产生过一次彻底的假阳性：GUI 实际跑的是 Lua 解释器（入口点被
   `onelua.c` 提供的 `WinMain` 抢走），而 `timeout` 返回的仍是"存活到超时 124"——
   因为 Lua REPL 也在等 stdin。判据必须落到"窗口存在 / 输出内容符合预期 / 副作用发生"，
   而不是"进程还没退出"。
6. **不自动 commit / push**：入库时机由用户把控。
7. **规格里的边界要写死在注释里**：Phase 1 已经因为 `natural_compare` 的 tie-break 方向
   不明踩过一次（实现与测试理解相反）。这类歧义人眼 review 很难发现。
8. **静默失败路径要有防御性断言。** 同一个 Phase 里的 `onelua.c` 混入问题，
   链接成功、启动成功、退出码正常，完全没有报错。凡是"失败时不出声"的地方
   （构建源文件清单、模板参数、路径拼接），都值得补一条显式检查。
